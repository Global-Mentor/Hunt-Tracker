# Устройство приложения

Один процесс Windows PowerShell читает оба журнала и обслуживает окно WinForms. HTML-источники только показывают опубликованное состояние. Сервера, сетевых запросов и отдельного процесса для каждого оверлея нет.

| Файл | Задача |
| --- | --- |
| `app/Launcher.ps1` | Запуск, возврат окна, остановка |
| `app/Files.ps1` | Чтение добавленных строк, атомарная запись, настройки и поиск Steam |
| `app/Tracker.ps1` | Источники логов, классификация, тестовые команды и публикация состояния |
| `app/Alerts.ps1` | Режимы алертов, задержка и сопоставление предполагаемого размена |
| `app/Statistics.ps1` | Матчи, карты, счетчики, сохранение и восстановление |
| `app/Panel.ps1`, `app/Dashboard.ps1` | Окно приложения и настройки |
| `client.js` | Очередь алертов, звук, подавление старых событий |
| `statistics.js` | Поля статистики, масштаб и скрытие устаревших данных |

## Данные

`_runtime/state.json` и `state.js` содержат одинаковое состояние. JS-файл позволяет OBS читать локальный источник без HTTP-сервера. После десяти секунд без свежего состояния оверлей скрывается.

Статистика сохраняется отдельно в `data/statistics.json`. Изменения отображения не затрагивают счетчики. Тестовые события попадают только в очередь алертов. Для статистической сессии и каждого матча создаются локальные UUID. Значения `mission=` и идентификаторы лобби для этого не используются.

Последние 50 завершенных матчей доступны в окне. Общие счетчики не ограничены этим списком. Новая сессия архивирует весь текущий снимок. Журналы классификации сохраняются в `Logs`; приложение их автоматически не удаляет.

## Алерты

`alertMode` принимает `kills`, `kills-deaths` или `trades`. Старые настройки без этого поля открываются в режиме `kills`. Старые снимки статистики получают счётчик `trades=0`, остальные значения сохраняются.

Событие запоминает режим при чтении. Первые два режима ждут 300 мс, режим разменов 500 мс. Неподтверждённое убийство определяется по отсутствию подходящего экрана смерти; обычный допуск сопоставления составляет 400 мс, в режиме разменов 500 мс. Это время чтения логов монотонным таймером процесса.

Предполагаемый размен требует двух событий NVIDIA в одном матче и поколении лога, одного неиспользованного экрана смерти и доступного Game.log в течение ожидания. Окно заканчивается через 500 мс после первого события. Три близких события или два экрана смерти исключают объединение; этот запрет сохраняется после удаления обработанных элементов очереди. При объединении пара удаляется целиком, в статистику добавляются убийство и смерть, в очередь отображения один `trade`. Отсутствие пары не отменяет обычную классификацию.

Каждый алерт содержит тип `kill`, `death` или `trade`. Клиент использует исходную анимацию и звук, меняет оттенок и подпись по типу. Выключенный источник не воспроизводит накопленные события при повторном включении. Команды теста проходят тот же фильтр режима, но не попадают в счётчики.

## Исход матча

- `MissionRequested` после наблюдавшейся загрузки и входа в игру с закрытым экраном смерти: предполагаемое выживание.
- `GameSessionEnded` или `UserRequested` после полностью наблюдавшейся загрузки и входа в игру с открытым экраном смерти: предполагаемая потеря охотника.
- Остальные завершения: неизвестный исход.

Потеря доступа к Game.log отменяет признак полного наблюдения. При перезапуске трекера, замене лога и смене процесса открытый матч завершается с неизвестным исходом. Уже имеющиеся строки замененного лога не добавляют матчи повторно. Переход соединения `Nub destroyed`, причина `Unknown`, код 11 во время загрузки не завершает матч.

## Проверки

Тесты используют отдельную временную папку Windows, искусственные журналы и процесс `HuntCombatFixture`. После проверки временные файлы удаляются. Ключ `-KeepArtifacts` оставляет их для разбора ошибки, `-IncludeWindowRestore` добавляет проверку системного восстановления окна.

Проверяются режимы алертов, границы окна размена, неоднозначные группы, классификация, дубликаты, частичные строки, переписывание больших логов, смена PID, повторный запуск, сохранение статистики, отключенные оверлеи, поведение окна и запуск чистого ZIP-пакета. Сборка включает только явно перечисленные файлы. Иконка и звук из исходного приложения сохраняются побайтно.

Для ручной проверки подключите оба HTML-файла в OBS, проверьте звук и выбранные поля, сверните приложение, закройте OBS и сыграйте матч. Затем откройте окно и сравните счетчики с событиями. Проверка на искусственных логах не подтверждает точность распознавания во всех игровых ситуациях.
