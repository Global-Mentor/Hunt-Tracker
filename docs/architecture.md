# Устройство приложения

Один процесс .NET 10 читает оба журнала и обслуживает окно WPF. Сбор выполняется в фоновой задаче, изменения состояния проходят последовательно через очередь команд. Окно получает снимки состояния и не обращается к игровым файлам. HTML-источники показывают опубликованные данные. HTTP-сервера и сетевых запросов во время работы нет.

| Компонент | Задача |
| --- | --- |
| `src/hunt-tracker-core/TrackerEngine.cs` | Сбор, очереди событий, публикация, команды |
| `Combat.cs` | Сопоставление убийств, смертей и предполагаемых разменов |
| `LogTail.cs` | Чтение новых строк без удержания файлов |
| `Statistics.cs`, `StatisticsStore.cs`, `HistoryBlocks.cs` | Счётчики, матчи, история, восстановление |
| `AppConfig.cs`, `AtomicFile.cs` | Настройки, поиск Steam, атомарные записи |
| `MediaCatalog.cs`, `Journal.cs` | Каталог медиа, журнал и фоновый экспорт |
| `src/hunt-tracker-desktop/App.xaml.cs` | Единственный экземпляр, запуск и остановка |
| `MainWindow.xaml`, `MainViewModel.cs` | Интерфейс WPF и привязки MVVM |
| `client.js`, `Overlay.html` | Анимация и звук алертов |
| `statistics.js`, `statistics.css`, `Statistics.html` | Виджет статистики OBS |

Пути файлов ядра в таблице относятся к `src/hunt-tracker-core`. Единственная внешняя библиотека приложения: CommunityToolkit.Mvvm для привязок и команд. Версии SDK и зависимостей закреплены в `global.json` и NuGet lock-файлах.

## Платформа

Приложение рассчитано на Windows 10/11 x64 и видеокарту NVIDIA. Для убийств и смертей читается журнал NVIDIA GfeSDK; включение записи Highlights в игре не является требованием. Наличие и доступность обоих логов проверяются во время работы.

## Независимые модули

Сбор и сохранение статистики работают всегда. `alertsEnabled` отключает игровые алерты, их очередь распознавания и периодическое сканирование медиа. `statisticsEnabled` отключает передачу статистики браузерному виджету. Настройки отдельных полей меняют только отображение. Режим `alertMode` не изменяет статистические счётчики; `detectTrades` отдельно включает экспериментальное распознавание разменов для статистики. Для новых настроек `detectTrades` включён, явное сохранённое значение сохраняется.

Смена путей выполняется в очереди команд сборщика. Новые источники читаются с конца файлов; сессия и готовые результаты сохраняются. Незавершённые сопоставления очищаются, чтобы сигналы из разных источников не объединялись. Если матч продолжается, его наблюдение отмечается как неполное. Сохранения интерфейса выполняются последовательно, чтобы отложенное изменение громкости не возвращало старые пути.

У свёрнутого или скрытого окна остановлен таймер обновления. После восстановления применяются последние данные. Повторная передача того же снимка не пересчитывает элементы интерфейса. История обновляется только на своей вкладке: каталог читает метаданные сессий, таблица показывает страницы по 100 матчей. Сортировка охватывает всю выбранную сессию. При сортировке по номеру от новых к старым чтение заканчивается после набора страницы. Остальные сортировки последовательно читают блоки в фоновой задаче, удерживая только кандидатов для страницы. Если выбор меняется во время загрузки, применяется последний запрос. События текущей игры не пересобирают открытый архив.

Снимки для окна копируют счётчики, карту и текущий матч без сериализации. Запрос истории получает отдельную копию последних матчей и ссылку на неизменяемые блоки. Старые форматы читаются целиком при первой миграции; новые сессии не удерживают всю историю в памяти. Изменяемые списки событий и словари статистики между сборщиком и окном не разделяются.

`autoRefreshMedia` разрешает обновление каталога каждые 2 секунды при включённых алертах. При отключении список обновляется вручную. Тест или включение модуля загружает каталог, если он ещё не загружен. После ошибки автоматическая попытка повторяется не чаще раза в 2 секунды. Звук и картинка выбираются независимо в папках `source/sounds` и `source/images`, типы `kill`, `death`, `trade`. Выбранные URL передаются в событии. Пустая категория не подменяется чужим медиа. Громкость 0 и параметр `?mute` исключают создание Audio и загрузку звука.

Обычный журнал JSONL содержит результаты распознавания, подключения, тесты и ошибки. `detailedDiagnostics` добавляет сигналы NVIDIA и открытие экрана смерти. Читаемый TXT создаётся только по кнопке, в отдельном потоке, без остановки сбора. Экспорт ограничен размером журнала на момент запуска; незавершённая последняя строка не попадает в отчёт. Ошибки медиа, записи статистики, браузерных источников и обновления окна обрабатываются отдельно. После ошибки сохранения данные остаются в памяти и запись повторяется через 3 секунды. Если основная запись недоступна при закрытии, приложение пытается сохранить самостоятельную копию в `_runtime/statistics-recovery.json`. При запуске более новая копия той же сессии восстанавливается автоматически и удаляется после успешной основной записи. Повреждённый основной JSON при восстановлении сохраняется в `data/recovery`. Если запись недоступна и в `data`, и в `_runtime`, сохранить данные после закрытия невозможно.

## Обмен с OBS

`_runtime/state.json` содержит служебное состояние для запуска и остановки. `_runtime/alerts.js` содержит очередь алертов и её настройки; `_runtime/statistics.js` содержит итоги и текущий матч. Полная история в браузерные файлы не передаётся. JS-файлы позволяют OBS использовать локальный источник без сервера.

Цикл сбора выполняется с паузой 25 мс при запущенной игре и 100 мс в ожидании. Браузер алертов читает состояние каждые 50 мс, выключенный модуль раз в секунду. Статистика читает состояние раз в 1000 или 5000 мс (`statisticsRefreshMs`), выключенный виджет раз в 5 секунд. Медленное обновление статистики не задерживает алерты. Тест выключенного алерта может дополнительно ждать до секунды, включение выключенной статистики до 5 секунд.

Публикация происходит при изменении и раз в 3 секунды для проверки связи. Каждый файл заменяется атомарно. Алерты публикуются до сохранения истории. После 10 секунд без свежего состояния источники скрываются. `revision` исключает повторную обработку одной публикации; `statistics_revision` меняется вместе с данными в памяти. При перезапуске клиенты учитывают новый `session`. Открытие источника не воспроизводит старые алерты.

## Хранение

`data/statistics.json` содержит итоги текущей сессии, текущий матч и ссылки на завершённые матчи. В формате версии 2 завершённые матчи лежат в `data/matches/<session-id>`. При изменении записывается только затронутый матч, затем атомарно заменяются метаданные со ссылками. Ссылка содержит хеш содержимого; при загрузке проверяются хеш, принадлежность сессии, структура матча и отсутствие дубликатов. До успешной записи метаданных прежнее состояние остаётся читаемым. Позднее событие обновляет свой матч по UUID, даже если начался следующий.

После накопления более 256 завершённых матчей старая часть переносится в неизменяемые блоки по 128 матчей в `data/history/<session-id>`. Формат версии 3 хранит ссылку на последний блок, число перенесённых матчей и ограниченный список свежих матчей. Блок содержит ссылку на предыдущий и хеш в имени файла; содержимое проверяется при чтении. Новые блоки записываются до метаданных. Память освобождается только после успешной замены метаданных. Поэтому отказ записи не отбрасывает ещё не сохранённые матчи. При длительной недоступности диска несохранённая история остаётся в памяти до успешной записи.

Форматы версий 1 и 2 остаются читаемыми. При первой перезаписи файла версии 1 его копия сохраняется в `data/migrations`. Повреждённый файл не заменяется пустой статистикой. «Новая сессия» сначала сохраняет предыдущую в `data/sessions`, затем создаёт новую. Для переноса нужна вся папка `data`, включая `matches` и `history`. Резервная копия при ошибке основной записи формируется потоково и содержит матчи без внешних ссылок. Ограничение чтения JSON-снимка: 64 МиБ; блока истории: 16 МиБ. Превышение выдаёт ошибку без изменения исходного файла.

UUID сессий и матчей создаются локально. `mission=` и ID лобби для этого не используются. `combat_events` хранит порядок последних 256 убийств и смертей матча; суммарные счётчики сохраняются полностью. Виджет создаёт не более 128 черепков и сообщает об ограничении в подсказке. У старых записей без порядка черепки сгруппированы по типу.

Очередь команд ограничена 64 запросами, за проход выполняется не более 32. Очереди сопоставления ограничены 128 событиями. При переполнении неоднозначный пакет отбрасывается без изменения счётчиков, появляется предупреждение, сопоставление возобновляется после паузы 1,5 секунды. Идентификатор NVIDIA ограничен 128 символами. Алерты принимают только локальные пути из папок медиа; адреса сети и переходы за пределы папки отклоняются.

## Распознавание

Алерты и статистика имеют отдельные очереди событий и экранов смерти. Один и тот же экран может быть использован один раз внутри каждой очереди. Событие сохраняет режим при чтении, поэтому смена настроек не меняет уже ожидающее статистическое решение. При штатном закрытии новые события NVIDIA больше не принимаются; уже прочитанные дожидаются своего окна 300/500 мс и сохраняются перед выходом.

| Назначение | Ожидание |
| --- | --- |
| Алерт `kills` | Без искусственного ожидания после чтения NVIDIA |
| Алерт `kills-deaths` | 300 мс |
| Алерт `trades` | 500 мс |
| Статистика без `detectTrades` | 300 мс |
| Статистика с `detectTrades` | 500 мс |

Быстрый режим показывает каждое новое событие NVIDIA, включая возможные смерти. Статистика отдельно различает убийства и смерти. Окна отсчитываются монотонным таймером от чтения логов, а не от игрового времени. Чтение файлов и браузер добавляют свою задержку.

Экран смерти сопоставляется с ближайшим событием NVIDIA в пределах 400 мс, с разменами 500 мс. Два разнесённых события по разные стороны экрана смерти не считаются неоднозначными только из-за похожего расстояния. Для практически одновременных запросов сохраняется консервативная обработка. Опоздавший экран смерти может дать ложное убийство. Неоднозначные события записываются в журнал без изменения счётчиков.

Предполагаемый размен требует двух событий одного матча и поколения лога, одного экрана смерти и доступного Game.log. Три близких события или два экрана исключают объединение. Окно заканчивается через 500 мс после первого события. При включённом статистическом распознавании пара добавляет убийство, смерть и размен. При режиме алертов `trades` пара показывает один двойной черепок. Эти решения независимы. Точность разменов не подтверждена игровыми тестами.

Тестовые события обходят режим и выключатель алертов, но не меняют статистику. Задержка теста соответствует выбранному режиму. Для убийства сохранена исходная анимация, для смерти красный оттенок, для размена две уменьшенные копии картинки.

## Матчи и файлы игры

Начало и карта читаются из Game.log. Выживание оценивается только для полностью наблюдавшегося загруженного матча, завершённого `MissionRequested` без открытого экрана смерти. Это оценка, а не доказательство эвакуации. По выбранному правилу все остальные завершённые матчи считаются «Не выжил» без добавления боевых смертей. Разрыв чтения, перезапуск, замена лога и смена процесса отменяют полное наблюдение. Переход `Nub destroyed`, `Unknown`, код 11 во время загрузки не завершает матч.

`LogTail.cs` входит в скомпилированное ядро. Без ожидающих боевых событий неизменившиеся логи проверяются по размеру, времени создания и записи. Полное открытие с проверкой 64-байтового хвоста выполняется не реже раза в секунду: так обнаруживается перезапись с прежним размером и временем. При новых строках NVIDIA и во время сопоставления доступность Game.log проверяется полным открытием. Блокировка файла в окне 300/500 мс не скрывается кэшем. Логи открываются с совместным чтением, записью и удалением; дескрипторы закрываются после прохода.

Буферы переиспользуются, за один проход читается не больше 1 МиБ. Незавершённая строка накапливается без повторного копирования всего префикса; большой буфер освобождается после обработки строки. Старые строки заменённого Game.log не добавляют матчи повторно. Если файл отсутствовал при запуске и был создан позже, его первые строки считаются новыми. Строки длиннее 1 МиБ отбрасываются целиком, включая остаток до перевода строки. Журнал трекера также разрешает совместный доступ. Найденный процесс игры отслеживается до выхода без повторного перебора всех процессов; после выхода поиск возобновляется.

## Проверки и сборка

Для сборки нужна точная версия .NET SDK из `global.json`, для проверок также Node.js и Python 3.9+. Решение: `HuntTracker.slnx`.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Test.ps1 -IncludePackage -IncludeWindowRestore
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Package.ps1
```

`Build.ps1` обновляет `.local/build/HuntTracker.exe`, который запускает `Start.bat` из исходников. После изменения C# пересоберите его. `Package.ps1` создаёт `dist/HuntTracker.zip` с текущим README. Готовый архив размещается в GitHub Releases отдельно от исходников.

`Build-Icon.ps1` пересобирает ICO из SVG в `src/hunt-tracker-desktop/assets`.

`scripts/Test.ps1` использует временные папки, искусственные логи и процесс-заглушку. Проверяются классификация, задержки, модули без OBS, тесты, медиа, миграция, ошибки записи и повторное сохранение, история, браузерные скрипты, окно и чистый ZIP. Параметр `-IncludeWindowRestore` проверяет возврат окна, повторный запуск и остановку крестиком. `-IncludePackage` собирает и запускает самостоятельный ZIP-пакет, проверяет загрузку CLR и WPF из встроенного комплекта, а не из установленного .NET. Проверки не запускают рабочий трекер и не меняют личную статистику.

`scripts/Measure.ps1 -Seconds 30` измеряет CPU, частную память, рабочий набор, дескрипторы и операции I/O отдельного свёрнутого экземпляра. Сценарии: ожидание игры без логов, процесс-заглушка с неизменными логами, дописывание 40 обычных строк в секунду. Перед каждым замером есть 5 секунд прогрева. CPU выводится относительно одного ядра и всей машины. Операции I/O учитывают обращения процесса, а не физические операции диска. OBS и настоящая игра в замер не входят. Параметр `-BuildDirectory` позволяет сравнивать разные сборки; временные данные удаляются после проверки.

`scripts/Build.ps1` собирает самостоятельный EXE для локального запуска со встроенным .NET. `scripts/Package.ps1` публикует самостоятельный EXE для Windows x64 со встроенным .NET и включает только перечисленные файлы. При первом запуске single-file EXE извлекает необходимые нативные библиотеки в кэш .NET пользователя. Личные настройки, история, логи и дополнительные медиа не входят в пакет. Исходные PNG и MP3 убийства сохраняются побайтно. Для ручной проверки OBS нужно обновить кэш источников после обновления приложения. Искусственные логи не подтверждают точность распознавания во всех игровых ситуациях.

Папки проекта: lowercase, несколько слов через дефис. Служебные `.github` и `_runtime` сохраняются. Внешние пути игры и NVIDIA не переименовываются.
